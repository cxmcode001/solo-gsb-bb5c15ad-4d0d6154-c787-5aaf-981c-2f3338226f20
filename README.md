# 会议议程实时重排（Meeting Agenda Live Re-arranger）

会议进行中，某项议程超时结束时，从当前时刻向后自动重排后续议程：

- **固定休息段不移动**：固定开始时间的休息段始终钉在原时间；
- **按优先级压缩**：先压缩优先级低、且非“不可压缩”的议程项，任何项都不会低于其最短时长；
- **冲突明确列出**：即使所有可压缩项都压到最短仍无法容纳时，页面顶部明确列出冲突议程与超出分钟数；
- **延期建议**：冲突面板可一键生成“移出本次会议”的延期建议 —— 仅针对未完成且可延期的议程（固定休息、已完成、不可压缩项不可移出），按 *优先级低 → 可释放计划时长大 → 原顺序* 反复试排，先预览将延期的项目与试排时间轴（不写数据库），确认后原子保存并立即重排，且可撤销；若延期全部候选仍无法消除冲突，会明确显示剩余超时分钟数并禁止确认；
- **双时间轴对比**：原计划 vs 实时新计划，压缩 / 完成 / 冲突分段着色，并标注当前时刻锚点与会议结束时间；
- **可撤销**：随时撤销上一步操作（实况录入、重置、延期确认，支持逐步撤销），也可一键重置实况。

技术栈：**FastAPI + SQLite（标准库 sqlite3）+ 原生 HTML/CSS/JavaScript**，无前端构建步骤。

---

## 一条命令启动（Docker Compose）

```bash
docker compose up --build
```

启动后在浏览器访问：

> **http://localhost:8000**

- 容器内服务监听端口 **8000**，已映射到宿主机同端口（`8000:8000`）。
- SQLite 数据文件保存在 Docker 卷 `agenda-data`（容器内 `/data/agenda.db`），容器重启后数据不丢失。
- 停止：`docker compose down`（加 `-v` 可同时删除数据卷）。

如宿主机 8000 端口被占用，修改 `docker-compose.yml` 中的端口映射，例如 `"8080:8000"` 后访问 http://localhost:8080 。

## 不用 Docker，直接本地运行

需要 Python 3.10+：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 **http://localhost:8000** 。数据库默认创建在 `data/agenda.db`，可用环境变量 `AGENDA_DB` 指定其他路径。

## 使用流程

1. **创建会议**：填写标题、开始 / 结束时间。
2. **添加议程项**：每项设置
   - 计划时长、最短时长（压缩下限）；
   - 优先级 `1（最低）～ 5（最高）`，压缩时从最低优先级开始；
   - “不可压缩”勾选后该项保持计划时长，绝不缩短；
   - 可用 ↑ / ↓ 调整议程顺序。
3. **添加固定休息段**：设置固定开始时间与时长（不能与其他休息段重叠）。
4. **录入实况**：会议进行中，在议程列表点“⏱ 实况”，填写该项**实际结束时间**并提交。系统立即：
   - 冻结已完成项；
   - 从该时刻起，把未完成议程依次装入固定休息段之间的空隙，必要时按优先级压缩；
   - 无法容纳时，红色面板列出冲突项与超出分钟数。
5. **生成延期建议**：冲突面板出现“🗓 生成延期建议”按钮。点击后弹出预览：列出将延期的议程（按 *优先级低 → 可释放计划时长大 → 原顺序* 选出）与延期后的试排时间轴，此时尚未写入任何数据。确认后系统原子保存延期状态并立即重排，该操作进入撤销链；若延期全部可延期议程仍有超时，弹窗会显示剩余超出分钟数且无法确认。已延期议程在列表中标记“📤 已延期”，不再占用时间轴，也不再要求录入实况。
6. **撤销 / 重置**：点“↩ 撤销上一步”逐步回退（实况录入、延期确认、重置均可撤销）；“重置实况”清除全部实际结束时间（重置本身也可撤销）。

## 重排规则（算法说明）

- 重排只影响**尚未录入实际结束时间**的议程；已完成项时间冻结。
- 未完成议程按顺序装入相邻固定休息段之间的空隙：
  - 空隙足够时保持计划时长；
  - 空隙不足时，按 **(优先级升序 → 可压缩空间降序 → 原顺序)** 压缩，直到容纳或全部到达最短时长；
  - 某项即便压到最短也放不进休息前空隙时，顺延到休息之后，并生成一条“无法在固定休息前安排”的冲突（注明超出分钟数）；
  - 最后一段空隙以会议结束时间为界，仍超出时生成“超出 N 分钟”冲突，超时段在时间轴上标红。
- 录入的实际结束时间落入固定休息段内时，重排锚点自动顺延到休息结束，并给出提示。

## 延期建议规则

- 仅**未完成**（未录入实际结束时间）且**可延期**的议程可被移出：固定休息不是议程项、已完成项时间冻结、不可压缩项不可移出；已延期的项不会重复选择。
- 从最早冲突开始反复试排：每轮重排一次，若仍有超时冲突，则按 **(优先级升序 → 可释放计划时长降序 → 原顺序)** 选出一项移出本次会议，直到冲突清零或没有候选。
- 预览接口只试排不写库；确认接口会基于当前状态重新计算建议，只有与预览完全一致且能清零冲突时才在一个事务内保存全部延期标记并写入撤销日志，随后立即返回重排结果。
- 无法清零时，预览会给出剩余超时分钟数与剩余冲突，确认请求会被拒绝（409）。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meetings` | 会议列表 |
| POST | `/api/meetings` | 创建会议 |
| GET | `/api/meetings/{id}` | 会议完整计划（items / breaks / 原计划 / 新计划 / 冲突） |
| POST | `/api/meetings/{id}/items` | 添加议程项 |
| DELETE | `/api/items/{id}` | 删除议程项 |
| POST | `/api/items/{id}/move` | 上移 / 下移（`{"direction":"up"}`） |
| POST | `/api/meetings/{id}/breaks` | 添加固定休息段 |
| DELETE | `/api/breaks/{id}` | 删除休息段 |
| POST | `/api/meetings/{id}/actuals` | 录入实际结束时间并触发重排 |
| POST | `/api/meetings/{id}/postpone-suggestion` | 生成延期建议预览（将延期的议程 + 试排时间轴，不写数据库） |
| POST | `/api/meetings/{id}/postpone` | 确认延期：原子保存并立即重排（可撤销），`{"item_ids":[...]}` 须与预览一致 |
| POST | `/api/meetings/{id}/undo` | 撤销上一步操作（实况录入 / 延期确认 / 重置） |
| POST | `/api/meetings/{id}/reset` | 重置全部实况（可撤销） |

交互式文档：启动后访问 http://localhost:8000/docs 。

```
└── requirements.txt
```
